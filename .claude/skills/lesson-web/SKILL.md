# 수업 웹 페이지 만들기

시작 전에 아래를 모두 직접 열어 읽는다. 앞 수업 하나만 본떠 만들지 않는다(2026-10-22 녹는점·끓는점 수업에서 품질이 떨어진 원인).
1. `docs/디자인기준.md` — 디자인의 유일한 기준(색·그림·배치·보고 전 점검, 좋은 예 사진)
2. `docs/작업방식_이삭T와_일하는_법.md` — 지난 반려 사례와 진행 방식
3. `docs/수업웹자료_표준개발절차.md` 2장 — 단계별 절차(자료 조사 ✅/🔎 표시 등)
4. 해당 단원 `curriculum/` 기준 문서
5. `tools/lesson-kit/README.md`의 "수업별 재사용 도구" — 같은 대단원 도구

시작하면 세션 이름을 `[대단원] 수업 이름 · 작업 종류`로 바꾼다(예: `Ⅰ 밀도 차를 이용한 분리 · 새 수업`).

## 0. 모드 고르기
- **프로토타입 모드**: 요청에 "프로토타입", "바로 만들어", "AUTO", "묻지 말고"가 있거나, 선생님이 자리를 비운다고 했을 때. **질문하지 않고 끝까지 만든다.** 1단계의 확인 질문을 건너뛰고, 기준 문서가 없으면 중학교 수준에서 보수적으로 만든다. 임의로 정한 것과 교육과정 미확인 항목은 모두 PR 설명에 적는다. 품질 기준은 낮추지 않는다(프로토타입이어도 첫 화면부터 완성도 있게).
- **디스커션 모드**: 그 외. 1단계대로 범위와 구성을 먼저 확인한다.

## 1. 범위 확인 (디스커션 모드)
1. `curriculum/`에서 해당 단원 기준 문서를 찾아 읽는다.
   - **없으면 여기서 멈추고** 사용자에게 교과서 해당 페이지(사진이나 요약)와 학년·단원명을 요청한다. 받으면 `curriculum/<학년>_<대단원>_<주제>.md`를 기존 문서와 같은 형식("사용 가능 / 초과 / 미확인")으로 만든다.
2. 요청이 모호하면(차시 수, 페이지 구성, 수업에서 하는 실험) 짧게 묻는다. 사용자가 "AUTO" 또는 "알아서"라고 하면 `lessons/ohm/` 구성을 기본값으로 쓴다.

## 2. 구성
- 폴더: `lessons/<영문-짧은-이름>/`
- 기본 페이지(필요한 것만):
  - `reading.html` — 읽기 3~4개 + 생각 멈춤 + 용어 풀이 + 퀴즈(5~10문항, 해설 포함)
  - `sim1-*.html`, `sim2-*.html` — 핵심 개념 시뮬레이션. 교과서 그림 형식을 빌려 와 교과서와 연결한다
  - `summary-*.html` — 짝짓기, 정리표, 짧은 글쓰기(저장하지 않음, 복사·인쇄만)
- `index.html` — `lessons/ohm/index.html`을 복사해 제목·부제·탭·`PAGES`만 바꾼다.
- 루트 `index.html`(허브) 스크립트 맨 위 `LESSONS`에 한 줄(제목·부제·썸네일 `lessons/<수업>/card.jpg` 또는 `card.svg`)을 넣고, `TABS`의 해당 단원 `lessons`에 수업 이름을 추가한다. 새 단원이면 `TABS`에 단원 한 줄을 추가한다.

## 3. 제작 규칙
- **제작 도구 `tools/lesson-kit/`을 쓴다** (README 참고). 원본은 `tools/lesson-kit/src/<수업>/`에 두고 `python tools/lesson-kit/build.py <수업>`으로 `lessons/<수업>/`을 만든다. 공통 블록(오류 상자, CSS, 퀴즈 엔진, 3D 도구, 2D 도식 도구, 탭 껍데기)은 다시 쓰지 않는다.
- **형식 고르기:** 구조·공간이 핵심이면 3D(three.js, `c3.js`), 흐름·양 비교·순환·과정·계산·사회 쟁점이 핵심이면 2D 도식·그래프(SVG, `flow.js`). 모든 시뮬레이션을 3D로 만들 필요는 없다. 어느 쪽이든 첫 버전부터 완성도 있게.
- 각 페이지는 CSS·JS가 모두 들어 있는 단독 HTML. 외부는 jsdelivr(Pretendard 등)만.
- 색·서체·그림·배치는 `docs/디자인기준.md`를 따른다(라스 파랑 하나+무채색, 그림은 판의 경계 실험실 수준). `lessons/ohm/`은 페이지 구성과 탭 껍데기만 참고하고 색·이름표는 따르지 않는다. 첫 버전부터 완성도 있게.
- `frontend-design` 스킬(`.claude/skills/frontend-design/`)은 절차(계획 → 흔한 기본값 점검 → 제작 → 스크린샷 비평)만 빌려 쓴다. 그 스킬의 "서체를 새로 고르고 과감하게"는 따르지 않는다. 서체·색·탭 껍데기·교육과정 규칙은 `docs/디자인기준.md`와 CLAUDE.md가 우선한다(이 스킬을 계속 둘지는 선생님 검토 중). 강조는 한 곳(주로 핵심 그림)에만 둔다. 문단 등장 효과(transform만)는 선생님이 원해서 유지한다.
- 등장 효과는 내용을 숨기지 않게, 스크립트는 블록별 try/catch.
- **한 화면 설계 (2026-10-15 선생님 지적):** 시뮬레이션 페이지는 태블릿 한 화면(탭 껍데기 안: 가로 1280×740, 세로 800×1220)에서 스크롤 없이 조작하고 결과까지 본다. 오른쪽 칸에 설명·기록표·정리·주석을 세로로 쌓지 않는다.
  - 실험 칸은 '고르기 → 예측 → 실행 → 결과'만 두고, 결과는 실행 버튼 바로 아래(또는 그림 위)에 나온다.
  - 관찰 기록·'왜 그럴까?'·정리는 칸 안의 탭(`.ptabs`)으로 나누고, 정리는 결과 상자에서 짧게 알려 준다.
  - 활동이 둘 이상이면 카드를 위아래로 붙여 쌓지 말고 머리의 활동 탭(`.ptabs.big`)으로 나눈다. 같은 화면에 둘 때는 카드 사이 24px 이상 띄우고 소제목으로 구분한다.
  - 그림 칸과 실험 칸은 높이를 맞춰(`align-items:stretch`) 빈 공간이 생기지 않게 한다. 모형 설명·출처 같은 주석은 그림 칸 아래 한 줄이나 탭 안으로 옮긴다.
  - 표가 길면 행·열을 바꿔 줄 수를 줄인다(예: 색 7가지 × 점 3가지 → 3줄).
- 제작자 표기("제작 · 성안중학교 이삭 T")는 넣지 않는다.
- 학생 개인정보를 받거나 저장하는 기능 금지.

## 4. 검사 (PR 전에 반드시)
1. 교육과정 대조: 모든 용어·공식·수치를 기준 문서와 대조해 초과·미확인 목록을 만든다. 초과는 고친다.
2. 화면 검사: `src/<수업>/qa.json`에 핵심 장면을 적고 `python tools/lesson-kit/qa_sheet.py <수업>`으로 1280×800, 800×1280 모음 사진과 오류 보고를 만든다. 글자 겹침·잘림, 그림 잘림, 멈춘 애니메이션, 콘솔 오류를 확인한다. 못 했으면 PR에 "화면 검사 못 함"이라고 적는다.
3. **움직임 검사 (2026-10-11 추가):** 모음 사진은 정지 한 장이라 움직임의 어색함이 안 보인다. 핵심 시뮬레이션·애니메이션 장면마다 버튼을 누른 뒤 여러 시점(시작·진행 중·끝)을 가로·세로로 연속 촬영해(Playwright 스크립트 또는 `shot.py`의 클릭·대기) 직접 보고 고친 뒤 보고한다. 스스로 묻기: ① 움직임이 실제 현상처럼 보이나(중력·포물선·경사를 따라 흐름·속도 변화, 직선으로 미끄러지기만 하지 않나) ② 그라디언트·질감·그림자 등 손으로 그린 수준인가, 도형 늘어놓기인가 ③ 글자 겹침·잘림 ④ 동작이 끝까지 이어지고 결과가 화면에 남나. 장면당 사진 4~6장으로 제한하고 핵심 장면에만 쓴다.
4. **한 화면 검사 (2026-10-15 추가):** `src/<수업>/fit.json`에 시뮬레이션의 첫 화면과 버튼을 누른 뒤 결과 화면을 적고 `python tools/lesson-kit/fit_check.py <수업> --shots <폴더>`로 가로 1280×740·세로 800×1220에서 넘치는 px을 잰다. 모두 '통과'가 될 때까지 배치를 고친다(글자를 작게 줄여 맞추지 말고 구조를 바꾼다).
5. **그림 속 글자 검사 (2026-10-22 추가):** `fit_check.py`는 화면 넘침만 재고 그림 안 이름표 겹침·잘림은 못 잡는다(용해도 차 분리 실험실에서 놓침). 가로·세로 사진에서 그림 칸을 확대해 이름표가 칸 끝에서 잘리거나 다른 글자와 겹치지 않는지 본다.
6. **디자인 점검:** `docs/디자인기준.md` 8장 점검 목록에 예·아니오로 답하고, '아니오'가 있으면 고친 뒤 보고한다.
7. 링크 검사: 탭·페이지 간 링크, 루트 목록 카드 링크.
