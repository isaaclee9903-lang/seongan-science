# 수업 발표 자료 만들기 (RAS 수업 → 발표)

학생이 혼자 읽는 RAS 수업(`lessons/`)과 달리, 선생님이 큰 화면에 띄워 **한 단계씩 넘기며** 가르치는 자료다. 2026-11-03 `presentations/motor-force/`(자기장 속 코일이 받는 힘, 25장)로 처음 만들었다. 기준 예시는 이 파일이다.

## 0. 흐름: RAS 먼저, 발표는 그 위에
1. **RAS 수업이 먼저 있어야 한다.** 해당 단원 `lessons/<수업>/`이 없으면 `lesson-web` 스킬로 먼저 만들고(검토·게시까지), 그다음 발표 자료를 만든다. 선생님이 "발표만 바로"라고 하면 묻고 진행한다.
2. 발표 자료는 RAS 수업의 **내용(읽기 글 순서, 생각 멈춤, 오개념, 퀴즈)**과 **그림(3D 장면, 2D 도식)**을 그대로 가져온다. 새 그림을 따로 그리지 않는다. 그래서 교육과정 범위도 RAS와 같다.
3. 기준 문서는 같은 `curriculum/` 문서다. 범위를 넘지 않는다(최우선 규칙은 `CLAUDE.md`).

## 1. 먼저 선생님과 정할 것 (디스커션)
선생님이 "프로토타입", "바로 만들어"라고 하지 않으면 만들기 전에 묻는다. 2026-11-03 정한 값이 기본값이다.
- 띄우는 곳: **교실 큰 화면, 선생님이 넘김** (16:9 고정, 글씨 크게)
- 빈칸: **화면에서만, 눌러야 열림** (학생은 공책에 씀). 단계를 넘겨도 저절로 열리지 않는다
- 분량: 한 차시에 **약 25장, 세세하게**
- 두는 곳: `presentations/<수업이름>/index.html`. 학생 허브(`index.html`)에는 넣지 않고 주소로만 연다

장 목차는 표로 먼저 보여 드리고 승인받는다. 묶음 예: 들어가기 → 탐구(예측 → 확인을 경우마다 한 장씩) → 기록표 정리 → 개념 → 방향·규칙 찾기와 단계별 연습 문제 → 활용 → 정리(빈칸 정리 + 확인 문제).

## 2. 화면 글 (선생님 지시)
- **개조식: "~함, ~됨, ~음"**. "~해요, ~돼요" 쓰지 않는다. 질문은 "~까?"로 끝낸다. 선생님께 드리는 답은 여전히 존댓말이다.
- 표지에 **'이삭 선생님'**을 넣는다(학생용 RAS 페이지의 제작자 표기 금지와 별개).
- 한 장에는 생각 하나만 둔다. 글은 세 줄 정도. 교과서 문장·용어를 그대로 쓴다.
- 교과서 도입 일화는 교과서 문장만 쓰고 그림·장면으로 늘리지 않는다.
- 빈칸 정답은 교과서 낱말로 쓴다. 연습 문제에는 단계(예: ① 자기장 방향 → ② 전류 방향 → ③ 손 대 보기 → ④ 힘)를 붙인다.

## 3. 만들기
틀은 `tools/lesson-deck/motor-force/`를 복사해 시작한다.
- `deck.tpl.html` — 발표 틀 전체. 고칠 곳은 두 군데다.
  - `<section class="slide">` — 장 내용. `data-s="1"`은 '다음'을 한 번 누르면 나타남. 빈칸은 `<span class="bk" data-a="정답"></span>`(번호는 ①부터 저절로 붙음). `data-group`이 아래 막대와 목차의 묶음 이름이다. 목록(`ol li[data-s]`)과 기록표 줄(`tr[data-row]`)은 지금 단계면 강조된다.
  - 블록 1의 `SCENES` — 장마다 3D 상태. `use`(장면 고르기), `layout`(`cover` 표지 / 기본 왼쪽 3D·오른쪽 글 / `text` 글만), `view`(보는 방향), `scene`(처음 상태), `steps[i]`(다음을 i+1번 눌렀을 때 바뀌는 것). 상태는 단계마다 **쌓여서** 계산되므로 뒤로 가도 같은 화면이 나온다. `show`는 적은 것만 켜진다.
- `build.py` — RAS 수업 시뮬레이션 페이지에서 3D 장면 코드(공통 3D 도구 `C3` + 장면 `try { … }` 블록)를 줄 번호로 잘라 틀에 끼우고, 발표용으로 몇 군데 바꾼다(`rep()`는 바꿀 문장이 정확히 한 번 있는지 확인함). lesson-kit 수업이면 `tools/lesson-kit/src/<수업>/`의 장면 원본이나 빌드된 `lessons/<수업>/sim*.html`에서 가져온다.
- 발표용으로 장면에 더할 것(motor-force에서 한 것):
  - **결과를 미리 보여 주지 않는 상태**: 예측 전에 전류 길만 보여 주려고 `freeze`(전류는 흐르지만 힘 0)를 넣음
  - 장마다 켜고 끄는 표시(예: (가)(나) 화살표, 부분 이름표 `parts`, 오른손 화살표 하나씩 `hs`, 오른손 창 크게 `bigHand`)
  - 장에 맞는 보는 방향(`VIEWS`)을 더함. **기둥·자석이 보려는 부분을 가리지 않는지** 꼭 찍어서 확인
  - 표지에서 천천히 돌기(`spin`, `controls.autoRotate`)
- 2D 그림 수업이면 `tools/lesson-deck/parallax/`처럼 한다(2026-11-08 별까지의 거리): 라스 페이지를 복사해 `?fig=이름`이면 그 그림만 화면 가득 보이게 하고, 발표 틀이 `DECKFIG.set(상태)`로 장마다 상태를 바꾼다. 도입 유튜브 영상은 `fig: 'video', yt: { id, start, end }`(앞부분만 보여 줄 때 `end`).
- 넘기기: → 스페이스 PageDown(발표용 리모컨) = 다음, ← PageUp = 이전, Home = 처음. 주소 끝 `#12`면 12장에서 시작.
- **빈칸 키 (모든 발표 기본, 2026-11-08 선생님 요청):** ↓ = 이 장에서 보이는 빈칸을 앞에서부터 하나씩 열기, ↑ = 마지막으로 연 빈칸 하나 닫기. 열 빈칸이 없으면 ↓는 다음, 닫을 빈칸이 없으면 ↑는 이전으로 넘어간다. 틀(`deck.tpl.html`)의 `openOne`·`closeOne`을 그대로 쓴다.

## 4. 화면 검사
- 미리보기는 로컬 서버(`.claude/launch.json`의 `site`)로 열고 1600×900 크기로 본다.
- **브라우저 창이 가려져 있으면 3D가 멈춘다**(화면 갱신이 오지 않음). 주소 끝에 `?raf=timer`를 붙이면 검사 중에도 움직인다. 이걸 모르면 "카메라가 안 움직인다"고 헛디버깅하게 된다.
- 장마다 마지막 단계까지 넘겨 찍는다. 움직이는 장면(그네 흔들림, 자석 뒤집기, 회전)은 몇 초 기다렸다 찍는다. 개발자 도구 콘솔에서 `SG.goto(n-1)` 뒤 `SG.next()`를 반복하면 빠르다.
- 확인할 것: 보는 방향에서 핵심 부분이 가려지지 않는가, 빈칸을 누른 뒤에도 키보드로 넘어가는가, 오른손 창 같은 작은 창이 이상하게 켜지지 않는가(상태값이 비면 `classList.toggle`이 매번 뒤집힘 → `show` 기본값을 채움), 글이 칸을 넘치지 않는가.

## 5. 올리기
- 같은 폴더를 여러 세션이 함께 쓰므로 브랜치를 바꾸지 않는다. scratchpad에 `git worktree add -b claude/<이름> <경로> origin/main`으로 작업 사본을 만들어 내 파일만 넣고 커밋·푸시한다.
- 미리보기 주소를 드리고 멈춘다. "게시해"라고 하면 작업 사본에서 `origin/main` 위에 `--no-ff` 병합 → `git push origin HEAD:main` → 실제 주소 `https://isaaclee9903-lang.github.io/seongan-science/presentations/<수업>/`가 열리는지 확인한다(1~2분 걸림).
