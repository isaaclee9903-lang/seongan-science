# 시험 정리본 만들기

수업 자료는 "왜 그런지"를 이해시키고, 시험 정리본은 "아는지 확인하고 모르는 것만 다시 보게" 한다. 그래서 길게 설명하지 않고, 선생님이 정한 비중대로 개념·문제·요약을 만든다. 기준 예시는 `lessons/exam-energy/`(원본 `tools/lesson-kit/src/exam-energy/`)다. 2026-11-06에 이 틀이 확정됐고, 왜 이렇게 됐는지는 맨 아래 '반려된 것'에 있다.

선생님께는 존댓말로, 영어 용어 없이 답한다. 먼저 읽을 문서: `docs/디자인기준.md`, `docs/작업방식_이삭T와_일하는_법.md`, 이번 범위의 `curriculum/` 문서.

## 1. 범위 확인: 첨부와 말씀이 맞는지 본다
시험 범위 번호와 첨부 교과서가 다를 수 있다(로마 숫자 Ⅲ·Ⅵ를 Ⅱ·Ⅳ로 적으신 적이 있다). 어긋나면 어떻게 이해했는지 먼저 말씀드리고 확인받는다.

## 2. 내용 뽑기 → 선생님 가중치 (만들기 전에 멈춘다)
선생님은 "바로 빌드하지 말고 내용부터"를 원한다. 비중을 모르고 만들면 대부분 다시 만들게 된다.

1. 교과서 PDF는 PyMuPDF(`fitz`)로 글을 뽑고, 그림·그래프가 답을 좌우하는 쪽은 이미지로 봐서 대조한다. `pdftotext`는 한글 경로에서 실패한다.
2. 항목을 소단원별로 쪼갠다(이번에 51개). 각 항목은 이름, 쪽, 한 줄 내용(계산 값 포함), 제안 가중치(상·중·하·뺌)로 적는다. 쪽 수는 교과서 본문 쪽이다.
3. `assets/weights.html`의 `D` 데이터를 바꿔 **`reports/` 같은 미리보기 서버가 여는 곳에 임시로 두고 브라우저 창으로** 띄운다. 대화창 안 그림표는 버튼이 눌리지 않아 반려됐다. 끝나면 임시 파일을 지운다.
4. 항목별 의견도 받는다. 선생님 요청이 교과서에 없는 예시일 수 있으니(수평면 탄성력·중력이 한 일 등) 그대로 반영하고 기준 문서의 미확인에 적는다.

함께 물을 것(모르는 것만): 시험 형식(객관식·논술형), 역산 출제 여부, 시험일, 넣지 않을 실험. 이번 기본값은 강의와 학생 휴대 전화·태블릿 겸용, 기본 가로형, 풀이 기록 남기지 않음이다.

## 3. 기준 문서
`curriculum/중3_시험대비_<범위>.md`에 가중치 표, 추가 요청, 교과서 표현(쪽 포함), 표기, 쓰지 않는 것, 미확인을 적는다. 예: `curriculum/중3_시험대비_일과에너지_에너지전환과보존.md`. '뺌' 항목과 그 낱말은 문제 선택지에도 쓰지 않는다.

## 4. 구성: 개념 / 문제 / 요약
| 탭 | 파일 | 내용 |
|---|---|---|
| 개념 | `cards.html` | 표지 + 개념 장. 가로로 넘김. 강의도 이 탭으로 |
| 문제 | `bank.html` | 단원·유형으로 고름. 계산은 숫자 바꿔 다시 풀기 |
| 요약 | `sheet.html` | 단원마다 글 한 장. 줄을 누르면 개념 창 |

만드는 법: `tools/lesson-kit/src/exam-energy/`를 `src/exam-<주제>/`로 복사해 내용만 바꾸고 `python tools/lesson-kit/build.py exam-<주제>`로 빌드한다. `lesson.json`은 `"shell": false`(탭 껍데기는 `index.tpl.html`). 로고·제목에는 허브 연결을 넣지 않는다(선생님 요청). 전체 화면 버튼은 휴대 전화까지 항상 머리 줄에 두고, 전체 화면에서는 아래 막대에 '원래 화면' 버튼이 나온다(`_big.js`). 전체 화면을 지원하지 않는 기기는 머리 줄만 숨긴다.

- `_qe.js` 문제 엔진, `_exam.css` 틀: 그대로 쓴다.
- `_bank.js` 문제 데이터, `cards.tpl.html`, `sheet.tpl.html`, `_ex.js` 그림: 내용을 바꾼다.

### 개념 장
- 한 장에 주제 하나. 왼쪽 그림, 오른쪽 글(세로 화면은 위아래).
- 글은 개조식(~함, ~됨)과 교과서 낱말로 세 줄 안팎. 핵심 낱말은 눌러서 여는 빈칸 `<span class="bk" data-a="정답"></span>`, 식은 `.eq`, 함정은 `.trap`.
- `<section class="slide" data-group data-title data-id data-fig data-qs="문제id,문제id">`. `data-id`는 요약의 연결 이름, `data-qs`는 "문제 풀기" 창에 뜰 문제 2개다. 문제 장을 따로 끼우지 않는다.
- 그림은 **장에 들어오면 바로 움직인다**(학생은 버튼을 잘 안 누른다). 그림 함수는 `{ play, stop }`을 돌려주고, 다시 보는 버튼은 남긴다.
- 그림은 같은 대단원 도구를 먼저 찾아 복사해 쓴다(`tools/lesson-kit/README.md`). 빈 칸이 있을 때만 새로 그린다. **기존 수업에 3D 모형이 있으면 그것을 가져온다**(`src/exam-electric-space/_3d.js`: 그 장을 처음 볼 때 three.js를 받아 만듦).
- 키보드: 왼쪽·오른쪽 키는 장 넘기기, 아래 키는 빈칸 하나 열기, 위 키는 다시 닫기.
- 선생님이 수업에서 하는 농담이 있으면 그 개념 장에 `.joke`로 넣는다. 스스로 지어내지 않는다.

### 문제
- 유형: 정의 빈칸, O·X, 계산, 자료 해석, 짝짓기, 서술형. 많을수록 좋다(이번 134개). 데이터는 한곳(`_bank.js`)에 두고 핵심 넘기기가 id로 가져간다.
- O·X는 교과서 '한눈에 정리하기'의 틀린 문장이 재료다. 객관식은 '단원 마무리 문제'를 고쳐 쓴다.
- 계산은 `calc(id, 단원, () => ({q, a, unit, why, d:[오답]}), 쪽)`로 만든다. 오답은 학생이 실제로 하는 실수(제곱 빠뜨림, 단위 혼동)로 정한다.
- 논술형이 있으면 서술형에 모범 답안과 "꼭 들어갈 말"을 넣는다.
- 풀이 기록은 저장하지 않는다. 틀린 문제 다시 풀기는 페이지를 닫으면 사라지는 메모리로만.

### 요약
- 그림 없이 글만, 단원마다 한 장. 위에 공식과 계산 예, 아래 두 칸에 뜻·관계·자주 틀리는 말.
- 줄마다 `data-go="개념id"`. 눌리는 줄에는 빠짐없이 `<span class="k">`로 파란 밑줄을 긋는다(공식은 이름, 틀리는 말은 맞는 답). 제목 옆에 "밑줄 친 말을 누르면 개념을 자세히 볼 수 있음"을 둔다. 처음 뜨는 안내 창은 쓰지 않는다.
- 개념 창은 `cards.html?float=1#개념id`를 띄우며 **빈칸은 열린 채로** 나온다. 닫으면 읽던 자리로 돌아온다.
- 인쇄는 A4 가로, 단원당 한 쪽. 안내와 밑줄은 인쇄에서 빠진다.

## 5. 내용 규칙
- 교과서 범위를 넘지 않고 표기를 따른다. 교과서에 없는 수치는 보고에 적는다.
- 수치는 계산해서 맞는지 본다. 틀린 정답은 시험 자료에서 가장 큰 사고다. 보고할 때 "정답은 선생님 검토가 필요하다"고 말한다.
- 색은 라스 파랑 하나+무채색, 틀린 표시만 붉은색, 그림 속 물체는 실제 색. 이모지·번짐·알약 이름표 없음(`docs/디자인기준.md`).

## 6. 검사
미리보기 서버(`.claude/launch.json`의 `site`)를 켠 뒤 실행한다.
```
python .claude/skills/exam-review/scripts/check_exam.py exam-<주제>
```
문제 데이터(중복 id, 계산 200회, 없는 문제·개념 연결, 밑줄 없는 줄), 네 화면 크기(태블릿 가로·세로, 휴대 전화 가로·세로)의 넘침, 문제 창과 개념 창 동작, 인쇄 쪽수를 본다. 사진은 `--shots <폴더>`로 찍어 **직접 눈으로** 본다. 숫자가 통과해도 그림 속 글자 겹침, 찌그러진 화살표, 끊겨 보이는 사람 그림은 안 잡힌다. 움직이는 그림은 여러 시점으로 찍는다.

자주 나는 실수:
- 숨은 칸은 크기가 0이라 그림을 미리 만들 수 없다. 장을 처음 볼 때 만든다.
- 클래스 이름이 부딪힌다. 버튼 `.btn.main`과 패널 `.main`이 겹쳐 버튼이 커진 적이 있어 패널은 `.qmain`이다. `.eqr span`이 밑줄 글자를 작게 만든 적도 있다.
- 움직이는 캔버스 그림은 인쇄하면 이름표가 어긋난다. 인쇄에 넣지 않는다.

## 7. 올리기
같은 폴더를 여러 세션이 함께 쓰므로 브랜치를 바꾸지 않는다. scratchpad에 `git worktree add -b claude/exam-<주제> <경로> origin/main`으로 작업 사본을 만들어 내 파일만 복사하고 커밋·푸시한다. 허브 `index.html`의 `LESSONS`와 `TABS`, `CLAUDE.md` 표, `tools/lesson-kit/README.md`는 작업 사본에서 고친다. 허브 카드 그림은 이름표 없는 차분한 `card.svg`.

미리보기 주소를 드리고 멈춘다. "게시해"라고 하시면 작업 사본에서 `git checkout --detach origin/main` → `git merge --no-ff claude/exam-<주제>` → `git push origin HEAD:main`을 하나씩 실행하고, 실제 주소에서 눌러 확인한다.

보고에는 탭별 내용, 확인한 것과 못 한 것(실제 기기·프린터), 임의로 정한 것, 눌러 볼 순서를 적는다.
