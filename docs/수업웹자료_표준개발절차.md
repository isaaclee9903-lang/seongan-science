# 수업 웹 자료 표준 개발 절차 (Claude 협업용)

> 안산 시화호 조력발전 R(Reading) 1차시 프로젝트(2026-09-29~30)에서 실제로 거친 과정을 정리하고, 다음 수업에도 쓸 수 있게 표준화한 문서예요.
> 새 수업을 시작할 때 이 문서를 새 프로젝트 폴더에 복사하고 **2장**부터 따라가면 돼요.
>
> **2026-10-10 갱신:** 지금은 이 저장소(`seongan-science`)에서 바로 만들고 **GitHub Pages**로 배포해요. 폴더는 `웹페이지/`·`GAS/` 대신 `tools/lesson-kit/src/<수업>/`(원본) → `lessons/<수업>/`(빌드 결과)을 써요. 1장과 부록 C의 GAS 내용은 지난 기록이에요.

### 1-2. 잘 된 것 (다음에도 그대로)
- **빌드 전에 디스커션부터:** 구조를 먼저 합의해서 만든 뒤에 크게 뒤엎는 일이 없었어요.
- **교과서 원문을 기준 문서로:** 이후 모든 콘텐츠를 이 문서와 대조했어요. 범위를 넘는 내용(패러데이 법칙, 송전 전압, 회전 속도-발전량 공식)을 걸러냈어요.
- **교과서 그림 형식 빌려 쓰기:** 에너지 막대그래프(그림 Ⅵ-9)와 흐름도(그림 Ⅵ-10)를 시뮬레이션에 그대로 옮겨서 수업 중 교과서와 연결하기 쉬웠어요.
- **단독 HTML 한 파일:** Lovable과 GAS 양쪽에 수정 없이 올릴 수 있었어요.
- **태블릿 기준 테스트:** 가로(1280×800)와 세로(800×1280) 두 화면에서 실제로 조작해 보고 고쳤어요.
- **사실은 원문으로 확인:** 자료마다 연도가 달랐던 것(해수 유통 1997/1998, 담수화 포기 2000/2001)을 찾아 "1990년대 후반", "2000년 무렵"으로 안전하게 썼어요.

### 1-4. 옴의 법칙 프로젝트(2026-10-01)에서 추가로 배운 것
| 있었던 일 | 원인 | 다음부터 |
|---|---|---|
| 1차본 그림을 "급조한 것 같다"며 전면 재작업 (수로 모형, 그래프 글씨 겹침, 전자가 안 움직임) | 기능부터 만들고 디자인·애니메이션을 뒤로 미룸 | **첫 버전부터 고품질**로 만들고, 보고 전에 스크린샷으로 겹침·움직임을 확인 |
| 그래프 결과만 있고 "왜 기울기가 다른지" 설명이 없음 | 결과 위주로 설계 | 그래프에는 **단계별 유도 패널**을 같이 넣는다 |
| GAS에서 읽기 본문이 통째로 안 보임 | 화면 감지(IntersectionObserver)가 GAS의 겹친 화면 안에서 안 불려 숨긴 내용이 안 나타남 | 등장 효과는 **내용을 숨기지 않는 방식**(위치 이동만)으로, 스크롤 + 주기적 확인 |
| GAS에서 JS로 그리는 그림만 비어 있음 (로컬에서는 재현 안 됨) | 큰 파일(약 100KB)을 붙여 넣다 끝이 잘렸을 가능성 | 스크립트를 **기능별 블록으로 나누고**, 실패하면 **화면에 빨간 상자**로 알리게 한다. 붙여 넣은 파일이 `</html>`로 끝나는지 확인 |
| 교과서 도입 실험(알루미늄 접시·네온전구)을 넣었다가 삭제 | 교과서에 있어도 실제 수업에서 안 하는 실험이었음 | 기획 때 **"수업에서 하는 실험·활동 목록"을 먼저 확인** |
| 제작자 표기를 나중에 추가 | 처음에 안 정함 | 모든 페이지 아래와 GAS 머리말에 **"제작 · 성안중학교 이삭 T"** 기본 포함  → **2026-10-07부터 제작자 표기를 넣지 않음**(선생님 요청) |

## 2. 표준 개발 절차

```
0. 준비 → 1. 교육과정 기준 → 2. 기획 디스커션 → 3. 자료 조사 → 4. 로드맵·배포 결정
      → 5. 시뮬레이션 제작 → 6. 읽기·퀴즈 제작 → 7. 지도안 → 8. 배포 → 9. 수업 후 개선
```

각 단계는 **넘겨줄 것 → Claude에게 할 말(복붙용) → 결과물 → 완료 확인** 순서로 되어 있어요.

---

### 0단계. 준비
- **넘겨줄 것:** 없음
- **할 일:**
  1. 바탕화면 등에 프로젝트 폴더를 만든다. 예: `○○중 과학 ○단원 ○○수업`
  2. Claude Code 세션을 **그 폴더를 선택해서** 시작한다.
  3. 이 문서를 폴더에 복사한다.
- **Claude에게 할 말:**
  ```
  이 폴더에서 새 수업 웹 자료를 만들 거야. '수업웹자료_표준개발절차.md'를 읽고 그 절차대로 진행해줘.
  지금은 0단계야. 부록 A의 CLAUDE.md 틀로 이 프로젝트용 CLAUDE.md를 만들어줘.
  ```
- **완료 확인:** 폴더에 `CLAUDE.md`가 생겼다.

---

### 1단계. 교육과정 기준 문서 (가장 먼저!)
- **넘겨줄 것:** 해당 단원 **교과서 페이지 사진 전부**, 앞 단원의 공식·용어 표기(예: 9.8mh, ½mv²)
- **Claude에게 할 말:**
  ```
  교과서 페이지를 올릴게. 이 내용을 잘 파악해서 절대 교육과정을 넘어서 수업을 구성하지 않도록
  '교육과정_기준_(학년과목)_(단원).md'로 저장해줘.
  소단원별 학습 목표·핵심 개념·활동·정리 문항, 용어 표기(띄어쓰기),
  사용 가능 / 사용 금지(초과) / 미확인 목록을 꼭 넣어줘.
  CLAUDE.md의 최우선 규칙에도 요약해 줘.
  ```
- **결과물:** 교육과정 기준 문서, CLAUDE.md 최우선 규칙
- **완료 확인:**
  - [ ] "사용 금지" 목록에 이 단원에서 넘기 쉬운 개념이 적혀 있다
  - [ ] 공식 표기와 기호(쓰는 것, 안 쓰는 것)가 정해져 있다
  - [ ] "미확인" 항목이 비어 있거나, 확인할 방법이 적혀 있다

---

### 2단계. 기획 디스커션 (만들지 않고 이야기만)
- **넘겨줄 것:** 수업 개요 한 덩어리
  - 대상 학년·단원, 지역 자원 또는 소재, 수업 모델(RAS 중 해당 요소), 차시와 시간
  - 학생 기기(태블릿/크롬북/PC), 원하는 구성(읽기, 시뮬레이션, 퀴즈, 표현 활동 등)
- **Claude에게 할 말:**
  ```
  아직 빌드하지 말고 디스커션만 하자. 수업 개요는 아래와 같아.
  (개요)
  교육과정 기준 문서 범위 안에서 페이지 구성, 기능, 시뮬레이션 로직, 데이터 구조를 제안하고,
  내가 정해야 할 것은 질문으로 물어봐줘.
  ```
- **결과물:** 섹션 구성, 결정 사항 → CLAUDE.md "결정사항"에 기록
- **완료 확인:**
  - [ ] 정량적인 부분(공식, 수치)이 모두 교과서 범위 안에 있다
  - [ ] 교과서 밖 관계는 "정성적 시각화"로 처리하기로 했다

---

### 3단계. 자료 조사
- **넘겨줄 것:** 없음 (필요하면 꼭 넣고 싶은 자료)
- **Claude에게 할 말:**
  ```
  수업에 필요한 자료를 인터넷에서 최대한 많이 찾아서 폴더에 넣어줘(링크든 PDF든).
  각 자료를 수업에 어떻게 녹일지 코멘트해 주고, 교육과정 기준 문서를 넘는 부분은 따로 표시해줘.
  ```
- **결과물:** `수업자료/수업자료_목록_및_활용안.md`, `수업자료/pdf/`
- **자료 목록의 표준 형식:**
  - 표시: ✅ 원문 확인 / 🔎 검색 결과로만 확인 / ⚠ 범위 초과 부분 있음
  - 섹션: 수업 흐름 순서대로(도입, 읽기 ①, 시뮬레이션, 읽기 ②, 표현)
  - 맨 앞: "검증된 핵심 사실" 표와 "주의할 점"(자료끼리 다른 수치, 헷갈리기 쉬운 설명)
  - 맨 뒤: "제외한 자료와 이유"
  - 사진: 라이선스(CC BY 등)와 출처 표기 문구
- **완료 확인:**
  - [ ] 학생 글에 쓸 사실은 ✅로 확인했다
  - [ ] 자료끼리 다른 수치는 범위 표현으로 정리했다

### 4단계. 로드맵과 배포 방식 결정
- **Claude에게 할 말:**
  ```
  로드맵 짜줘. (만들고 싶은 것 나열). 45분 시간 배분도 같이 해주고, 더 좋은 구성이 있으면 제안해줘.
  배포는 GitHub Pages(seongan-science 저장소)야.
  ```
- **여기서 꼭 정할 것:**
  - 만들 페이지 목록과 순서
  - 배포는 **GitHub Pages**가 기본 (부록 C)
  - 결과 저장·게시판이 필요한지 (정적 페이지라 저장은 안 됨. 필요하면 구글 폼·GAS 연동을 따로 제안)
- **완료 확인:** `tools/lesson-kit/src/<수업>/lesson.json`에 탭(페이지) 목록이 적혀 있다

### 5단계. 시뮬레이션 제작
- **Claude에게 할 말:**
  ```
  시뮬레이션 (이름)을 html 코드로 만들어줘. 학생 기기는 태블릿이야.
  퀄리티는 아주 좋게, 애니메이션과 디테일을 살려줘. 교육과정 기준 문서를 지켜야 해.
  만든 뒤에 태블릿 가로·세로 화면에서 직접 조작해 보고 문제를 고쳐줘.
  ```
- **설계 기준 (부록 B의 디자인 기준 포함):**
  - 교과서 그림 형식(막대그래프, 흐름도 등)을 그대로 빌려 쓴다
  - 교과서의 비교 실험 구조를 옮긴다 (예: (가) 발전기 없음 / (나) 발전기 있음)
  - 교과서 밖 수치는 숫자 없이 연출로만 보여주고, 화면 아래에 "개념 이해를 위한 모형" 안내를 넣는다
  - 실제와 다르게 보이는 연출(오개념)을 피한다 (예: 기기를 더 켜도 교실 전등은 어두워지지 않음)
  - 관찰 미션이나 "예상하고 켜기" 같은 탐구 장치를 넣는다
- **결과물:** `tools/lesson-kit/src/<수업>/sim○-영문이름.tpl.html` → 빌드 후 `lessons/<수업>/sim○-영문이름.html`
- **완료 확인:**
  - [ ] 태블릿 가로·세로에서 손가락으로 모든 조작이 된다
  - [ ] 화면의 모든 공식과 용어가 교과서 표기와 같다
  - [ ] 콘솔 오류가 없다
  - [ ] 스크린샷으로 글자 겹침이 없고 애니메이션이 실제로 움직인다
  - [ ] 제작자 표기가 없다 (2026-10-07부터 넣지 않음)

### 6단계. 읽기·퀴즈 제작
- **Claude에게 할 말:**
  ```
  찾은 자료로 R(Reading)에 해당하는 읽을거리와 퀴즈를 html로 만들어줘.
  기사 문장은 복사하지 말고 학생 수준으로 새로 쓰고, 카드마다 출처를 달아줘.
  ```
- **표준 구성:**

## 부록 C. 배포 방식 선택과 GAS 키트 (지난 기록)

> 2026-10-10부터 배포는 GitHub Pages로 통일했어요. 아래 GAS 내용은 학생 답 저장이 꼭 필요할 때만 참고해요.

| | GAS (기본) | Lovable (예비) | 정적 호스팅 (GitHub Pages 등) |
|---|---|---|---|
| 비용 | 무료 | 크레딧 | 무료 |
| 주소 | 길다 (QR 권장) | 깔끔 | 깔끔 |
| 결과 저장·게시판 | 스프레드시트로 쉽게 | 데이터베이스 필요 | 불가 |
| 개인 계정 표시 | 상단 안내 줄 있음 | 없음 | 없음 |

**GAS 키트 재사용법** (`GAS/` 폴더를 새 프로젝트로 복사한 뒤)
1. `Code.gs`: `PAGES` 배열을 새 페이지 이름으로 바꾸고, `setTitle` 제목을 바꾼다.
2. `Index.html`: 제목 문구, 탭 버튼(`data-page`)과 iframe(`data-page`, `data-embed="1"`)을 페이지 수만큼 맞춘다.
3. 각 페이지 HTML을 Apps Script에 `PAGES`와 같은 이름으로 만든다(`+ → HTML`).
4. 배포: 새 배포 → 웹 앱 → 실행: 나 → 액세스: 모든 사용자. 수정할 때는 **배포 관리 → 새 버전**으로 해야 주소가 유지된다.

**GAS에서 알아둘 점:**
- HTML 안의 viewport 설정은 무시되니 `addMetaTag`로 넣는다.
- 페이지는 같은 출처 iframe(srcdoc)으로 띄워야 탭 이동 메시지가 전달된다.
- 코드에 보이지 않는 줄 바꿈 문자(U+2028/2029)가 있으면 저장이 실패한다.
- IntersectionObserver에 기대는 기능은 GAS 안에서 동작하지 않을 수 있다. JS가 실패해도 내용은 보이게 만든다.
- JS로 그리는 그림이 있는 페이지는 스크립트를 기능별 블록(각각 try/catch)으로 나누고, 오류·미실행을 화면 아래 빨간 상자로 표시한다. 로컬 흉내로는 GAS 문제가 재현되지 않을 수 있어서 이 상자가 유일한 단서가 된다.
- 파일이 80KB를 넘으면 붙여 넣을 때 끝이 잘리지 않았는지(`</html>`로 끝나는지) 반드시 확인한다.
- 수정 후에는 다시 붙여 넣을 파일 목록과 "배포 관리 → 편집 → 새 버전"을 함께 안내한다.
