## 1. 지난 프로젝트에서 배운 것 (요약)
2026-09~10월 시화호 조력발전(GAS 배포)과 옴의 법칙 프로젝트 기록이에요. 자세한 반려 사례는 `docs/작업방식_이삭T와_일하는_법.md` 2장에 있어요. 지금도 그대로 쓰는 습관만 남겨요.

- 교과서 그림 형식(막대그래프, 흐름도, 탐구 과정)을 빌려 와 교과서와 연결한다.

## 2. 표준 개발 절차

```
0. 준비 → 1. 교육과정 기준 → 2. 기획 디스커션 → 3. 자료 조사 → 4. 로드맵·배포 결정
      → 5. 시뮬레이션 제작 → 6. 읽기·퀴즈 제작 → 7. 지도안 → 8. 배포 → 9. 수업 후 개선
```

각 단계는 **넘겨줄 것 → Claude에게 할 말(복붙용) → 결과물 → 완료 확인** 순서로 되어 있어요.

### 2단계. 기획 디스커션 (만들지 않고 이야기만)
- **넘겨줄 것:** 수업 개요 한 덩어리

  ```
  아직 빌드하지 말고 디스커션만 하자. 수업 개요는 아래와 같아.
  ```

- **완료 확인:**

### 5단계. 시뮬레이션 제작
- **Claude에게 할 말:**
  ```
  시뮬레이션 (이름)을 html 코드로 만들어줘. 학생 기기는 태블릿이야.
  퀄리티는 아주 좋게, 애니메이션과 디테일을 살려줘. 교육과정 기준 문서를 지켜야 해.
  만든 뒤에 태블릿 가로·세로 화면에서 직접 조작해 보고 문제를 고쳐줘.
  ```
- **설계 기준 (부록 B의 디자인 기준 포함):**
  - 교과서 그림 형식(막대그래프, 흐름도 등)을 그대로 빌려 쓴다
  - 교과서의 비교 실험 구조를 옮긴다 (예: (가) 발전기 없음 / (나) 발전기 있음)
  - 교과서 밖 수치는 숫자 없이 연출로만 보여주고, 화면 아래에 "개념 이해를 위한 모형" 안내를 넣는다
  - 실제와 다르게 보이는 연출(오개념)을 피한다 (예: 기기를 더 켜도 교실 전등은 어두워지지 않음)
  - 관찰 미션이나 "예상하고 켜기" 같은 탐구 장치를 넣는다
- **결과물:** `tools/lesson-kit/src/<수업>/sim○-영문이름.tpl.html` → 빌드 후 `lessons/<수업>/sim○-영문이름.html`
- **완료 확인:**
  - [ ] 태블릿 가로·세로에서 손가락으로 모든 조작이 된다
  - [ ] 화면의 모든 공식과 용어가 교과서 표기와 같다
  - [ ] 콘솔 오류가 없다
  - [ ] 스크린샷으로 글자 겹침이 없고 애니메이션이 실제로 움직인다
  - [ ] 제작자 표기가 없다 (2026-10-07부터 넣지 않음)

### 6단계. 읽기·퀴즈 제작
- **Claude에게 할 말:**
  ```
  찾은 자료로 R(Reading)에 해당하는 읽을거리와 퀴즈를 html로 만들어줘.
  기사 문장은 복사하지 말고 학생 수준으로 새로 쓰고, 카드마다 출처를 달아줘.
  ```
- **표준 구성:**
  - **첫 화면:** 핵심 질문과 실제 사진(출처 표기)
  - **읽기 ①:** 지역 이야기(타임라인 카드) → 생각 멈춤 → 개념 읽기(공식 예시 계산) → 시뮬레이션 연결 버튼
  - **퀴즈 ①:** 3문항 (OX, 빈칸, 선택/계산)
  - **읽기 ②:** 개념 확장 → 생각 멈춤 → 에너지 흐름 정리 → 시뮬레이션 연결 버튼
  - **퀴즈 ②:** 3문항
  - **정리:** 흐름 빈칸 채우기, 결과(점수, 틀린 문제 다시 보기), 참고 자료 목록
  - **읽기 도우미:** 용어 풀이 풍선, 글자 크기 버튼, 진행 표시줄
  - **빈칸 입력:** 태블릿에서 타이핑하지 않도록 단어 칩을 눌러 채운다
- **수정하기 쉽게:** 퀴즈는 스크립트 맨 위 `QUIZ` 데이터에, 페이지 주소는 `LINKS`에, 용어 풀이는 `GLOSSARY`에 모은다
- **결과물:** `tools/lesson-kit/src/<수업>/reading.tpl.html` → `lessons/<수업>/reading.html`
- **완료 확인:**
  - [ ] 모든 사실 문장에 출처가 있고, 🔎 자료만으로 쓴 문장이 없다
  - [ ] 퀴즈 정답·해설이 교과서 정리 문항과 표현이 맞다

## 부록 A. CLAUDE.md 틀

```markdown
# (학교) (학년 과목) (단원) – (수업 이름)

## 교육과정 범위 (최우선 규칙)
- 모든 콘텐츠는 `교육과정_기준_(…).md`의 범위를 절대 넘지 않는다. 작업 전에 이 파일을 읽는다.
- 공식 표기: (예: 위치 에너지 9.8mh, 운동 에너지 ½mv²). 쓰지 않는 기호: (예: g)
- 금지: (이 단원에서 넘기 쉬운 개념 나열)
- 교과서에 없는 정량 관계는 숫자 대신 정성적 시각화로 표현한다.

## 진행 방식
- 학생 기기: (태블릿 등)
- 배포: GitHub Pages (seongan-science). 원본은 `tools/lesson-kit/src/<수업>/`, 빌드 결과는 `lessons/<수업>/`.
- 페이지는 CSS·JS가 모두 들어 있는 단독 HTML로 만든다.
- 사용자가 요청하기 전에는 빌드하지 않는다(기획 단계).

## 자료
- 자료 목록: `수업자료/수업자료_목록_및_활용안.md`
- 지역 자원의 특수성: (예: 시화호는 밀물 때 발전)

## 결정사항
- (구성, 퀴즈 형식, 보류한 기능 등)
```

## 부록 C. 배포 방식 선택과 GAS 키트 (지난 기록)

> 2026-10-10부터 배포는 GitHub Pages로 통일했어요. 아래 GAS 내용은 학생 답 저장이 꼭 필요할 때만 참고해요.

| | GAS (기본) | Lovable (예비) | 정적 호스팅 (GitHub Pages 등) |
|---|---|---|---|
| 비용 | 무료 | 크레딧 | 무료 |
| 주소 | 길다 (QR 권장) | 깔끔 | 깔끔 |
| 결과 저장·게시판 | 스프레드시트로 쉽게 | 데이터베이스 필요 | 불가 |
| 개인 계정 표시 | 상단 안내 줄 있음 | 없음 | 없음 |

**GAS 키트 재사용법** (`GAS/` 폴더를 새 프로젝트로 복사한 뒤)
1. `Code.gs`: `PAGES` 배열을 새 페이지 이름으로 바꾸고, `setTitle` 제목을 바꾼다.
2. `Index.html`: 제목 문구, 탭 버튼(`data-page`)과 iframe(`data-page`, `data-embed="1"`)을 페이지 수만큼 맞춘다.
3. 각 페이지 HTML을 Apps Script에 `PAGES`와 같은 이름으로 만든다(`+ → HTML`).
4. 배포: 새 배포 → 웹 앱 → 실행: 나 → 액세스: 모든 사용자. 수정할 때는 **배포 관리 → 새 버전**으로 해야 주소가 유지된다.

**GAS에서 알아둘 점:**
- HTML 안의 viewport 설정은 무시되니 `addMetaTag`로 넣는다.
- 페이지는 같은 출처 iframe(srcdoc)으로 띄워야 탭 이동 메시지가 전달된다.
- 코드에 보이지 않는 줄 바꿈 문자(U+2028/2029)가 있으면 저장이 실패한다.
- IntersectionObserver에 기대는 기능은 GAS 안에서 동작하지 않을 수 있다. JS가 실패해도 내용은 보이게 만든다.
- JS로 그리는 그림이 있는 페이지는 스크립트를 기능별 블록(각각 try/catch)으로 나누고, 오류·미실행을 화면 아래 빨간 상자로 표시한다. 로컬 흉내로는 GAS 문제가 재현되지 않을 수 있어서 이 상자가 유일한 단서가 된다.
- 파일이 80KB를 넘으면 붙여 넣을 때 끝이 잘리지 않았는지(`</html>`로 끝나는지) 반드시 확인한다.
- 수정 후에는 다시 붙여 넣을 파일 목록과 "배포 관리 → 편집 → 새 버전"을 함께 안내한다.
