# 이삭 T와 일하는 법 (옴의 법칙·조력발전 프로젝트에서 배운 것)

클라우드 세션은 선생님 PC의 Claude 메모리를 볼 수 없다. 2026년 9~10월에 두 수업(중3 시화호 조력발전, 중2 옴의 법칙)을 만들면서 선생님에게 지적받고 확인받은 내용을 여기에 옮겨 둔다. **새 수업을 만들기 전에 이 문서를 읽는다.**

## 1. 선생님이 원하는 진행 방식
- 기본은 "디스커션 먼저, 요청하면 빌드"다. 단, 선생님이 **"프로토타입", "바로 만들어", "AUTO"**라고 하면 묻지 않고 끝까지 만든다. 애매한 결정은 합리적인 기본값으로 정하고 PR 설명의 "임의로 정한 것"에 적는다.
- 선생님은 결과물을 태블릿에서 직접 열어 보고 판단한다. 말로 하는 설명보다 **완성된 화면**이 중요하다.
- 사용자에게는 항상 존댓말로 답한다.

## 2-1. 선생님 의견 (2026-10-05)
- 3D가 나쁘다는 것은 아니지만, **글의 특성에 따라 2D 도식·그래프 시뮬레이션이 더 효과적일 수 있다.** 흐름·양 비교·순환·사회 쟁점은 2D, 구조·공간은 3D를 먼저 검토한다.
- 「사진 한 장의 여행」 결과물에 매우 만족. 다만 제작 시간이 길었으므로 `tools/lesson-kit/`을 쓰고, 화면 검사는 모음 사진 한 장으로 한다.

## 3. 화면·코드 기준 (요약, 자세한 값은 표준개발절차 부록 B)
- 태블릿 가로 1280×800, 세로 800×1280 둘 다. 900px 미만에서 한 줄 배치. 버튼 44~56px, 슬라이더 손잡이 34px 이상.
- 본문 18px, 줄 간격 1.8, `word-break: keep-all`. 서체 Pretendard. 색은 `lessons/ohm/`과 같게.
- 빈칸 문제는 태블릿 타이핑 대신 **단어 칩을 눌러 채우기**.
- 퀴즈는 스크립트 맨 위 `QUIZ` 데이터, 링크는 `LINKS`, 용어 풀이는 `GLOSSARY`에 모아 선생님이 고치기 쉽게.
- 등장 효과는 **내용을 숨기지 않는 방식**(transform만). opacity:0으로 숨겼다가 IntersectionObserver로 보여 주는 방식은 iframe 안에서 안 불려 본문이 통째로 사라진 적이 있다.
- 스크립트는 기능별 `<script>` 블록 + try/catch. 실패하면 화면 아래 빨간 상자로 알린다.
- `prefers-reduced-motion` 대응. 이모지·과한 장식·마케팅 말투 금지("AI티" 금지).
- 학생 이름·점수 저장 금지. 글쓰기는 복사·인쇄만.

## 4. 교육과정
- `curriculum/`에 기준 문서가 있으면 그 범위 안에서만 만든다.
- 없으면: 디스커션 모드에서는 교과서 페이지를 요청한다. **프로토타입 모드에서는 멈추지 않는다.** 일반적인 한국 중학교 과학 교육과정 수준에서 보수적으로 만들고, 확신이 없는 용어·공식·수치는 모두 PR의 "교육과정 미확인 목록"에 적는다. 선생님이 나중에 교과서와 대조한다.
- 표기 예: 2022 개정 중2 전기 단원은 I, V, R / A, mA, V, Ω, I = V/R. 중3 에너지 단원은 위치 에너지 9.8mh, 운동 에너지 ½mv² (g, √(2gh) 쓰지 않음). 띄어쓰기는 교과서를 따른다(빛에너지·열에너지는 붙이고, 나머지 "~ 에너지"는 띄움).

## 5. 수업 구성의 기본형 (옴의 법칙)
`lessons/ohm/` = 탭 껍데기 `index.html` + 페이지 4개
1. 읽기·퀴즈: 핵심 질문 → 읽기 → 생각 멈춤 → 퀴즈 → 읽기 → 퀴즈 → 결과(점수, 틀린 문제 다시 보기). 용어 풀이 풍선, 글자 크기 버튼, 진행 표시줄. 시뮬레이션으로 가는 버튼(`postMessage({type:'ras-nav', target})`)
2. 시뮬레이션 1: 비유 모형과 실제를 나란히, 동기화 (예: 수로 모형 ↔ 회로)
3. 시뮬레이션 2: 교과서 탐구 과정을 단계별 가상 실험으로
4. 정리·글쓰기: 짝짓기, 정리표, 계산 연습, 짧은 글쓰기
새 수업도 이 틀을 기본값으로 쓰고, 주제에 맞지 않으면 줄인다.
